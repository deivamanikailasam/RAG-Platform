# ADR-0020: Use Prometheus, Alertmanager and Grafana with SLO-based alerting

- **Status:** Accepted
- **Date:** 2026-10-12
- **Deciders:** deivamanikailasam

## Context
We need durable metrics, dashboards and alerts that reflect user experience, across our own services
(OpenTelemetry) and off-the-shelf components (Prometheus /metrics), without alert fatigue.

## Decision
Prometheus 3.13 LTS (digest-pinned) stores metrics: OTLP push from the Collector
(--web.enable-otlp-receiver, promoted service.version and environment labels) plus scrapes of
Keycloak, OPA (metrics-only token), Qdrant (read-only key), Postgres (postgres_exporter as
pg_monitor role rag_metrics), TEI and the Collector. Retention 15 days / 5 GB. Search SLO: 99%
success over 28 days, p95 < 2 s; multi-window burn-rate alerts (14.4x over 1h+5m = critical,
6x over 6h+30m = warning). Security alert on any policy/query mismatch. Every rule is unit-tested
with promtool in `just check`. Alertmanager 0.34 routes by severity with inhibition. Grafana 13
with provisioned data sources and dashboards generated by scripts/build_dashboards.py (drift-checked).
Histogram buckets are explicit, in seconds, with an edge at each latency objective; alert-worthy
counters start at 0.

## Alternatives considered
| Option | Pros | Cons | Why not chosen |
|---|---|---|---|
| Grafana Mimir / VictoriaMetrics / Thanos | Scale-out, long retention | More components | Single-node Prometheus is enough locally; revisit for scale |
| Grafana-managed alerting only | One UI | Alerts tied to Grafana; harder to unit-test | Prometheus rules + promtool tests are reviewable code |
| SaaS (Datadog, Grafana Cloud…) | No operations work | Cost; data leaves the machine | Our Collector can add a SaaS exporter later |
| Threshold alerts on raw error counts | Simple | Noisy; ignores traffic volume | Burn-rate alerts match user impact |

## Consequences
+ User-centred reliability targets with tested, low-noise alerts and runbooks.
+ Everything (scrapes, rules, routes, data sources, dashboards) reviewed in Git.
- Prometheus and Alertmanager UIs have no auth: localhost only here; a proxy in production.
- Single Prometheus = single point of failure for alerting (HA pair + Alertmanager cluster later).

## Revisit when
Retention beyond 15 days is required, multiple environments share alerting, or traffic needs HA.
